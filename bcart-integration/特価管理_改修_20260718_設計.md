## 改修2: 特値をactivity側でも除外（Takashi確定・sales-db）

`export_price_audit.py` の**activity CSV**（③休眠特価の判定用）が特値を除外していない。seed（①②用）は既に `特値 != '特'` で除外済みだが、activityは `明細区分=''` だけ。→ **activityにも `特値 != '特'` を追加**して機能全体で特値を無視する。

該当SQL（`q_activity`）を次に変更:
```sql
SELECT DISTINCT 親子コード AS 得意先コード, 商品ｺｰﾄﾞ AS 商品コード
FROM 売上明細
WHERE 売上日 >= ? AND 明細区分 = '' AND 特値 != '特'
```
- 影響: 「特値でその時だけ買った」ペアが"実績なし"扱いになり、③休眠特価として拾われ得るようになる（＝特値は継続取引ではない、というTakashiの整理と一致）。①②は元々特値除外なので変化なし
- 実施後: `py -3.12 export_price_audit.py` を再実行してactivity CSVを更新（activity行数が微減するはず）。VERSIONを1.1.0に

## 改修3: 「選択会員をグループに追加」動線（Takashi確定＝会員追加のみ）

**背景**: 特価は個別特価より「導入サロングループを作って特別価格設定」で運用することが多い。特価もれ検出①の結果から、選択した会員を（既存/新規）グループのメンバーに追加できる動線が欲しい。**会員をグループに追加するだけ**（商品の特価は追加後に特別価格設定で通常通り設定する＝Takashi選択）。

### 3-1. GAS新アクション `addCustomerCodesToGroup(params)`（Code.gs v2.22.0・特別価格系認証ゾーン）
`saveCustomerGroup`は全項目上書き型で会員を"置換"してしまうため流用不可。**customer_codes列(7列目)だけを追記更新**する専用アクションを新設する。

Request:
```json
{ "action": "addCustomerCodesToGroup",
  "group_id": "G...",         // 既存グループに追加する場合
  "group_name": "○○グループ",  // 新規作成する場合（group_id未指定時）
  "codes": ["4173", "4277"] }
```
実装仕様:
- `codes` は特価もれ検出①で選択した行の`customer_code`（重複除去済み）
- **既存グループ（group_id指定）**: `findGroupRowValues(group_id)`で行取得→既存customer_codes(列7)をカンマ分割→`codes`とマージ（**`normCode_`で正規化重複除去**・表示はraw文字列を保持）→列7だけ`setNumberFormat('@')`＋`setValue`で書き戻す。**member_ids/note/use_view_filterは触らない**。戻り値`{ ok, group_id, group_name, added: 実際に増えた件数 }`
- **新規グループ（group_id無し・group_name有り）**: `saveCustomerGroup`の新規作成部を参考に1行append（group_name・member_ids空・customer_codes=codes）。新group_idを返す
- addHistory: type`グループ会員追加(特価もれ)`、after`グループ名 / N件`
- ⚠️ 認証は既存の特別価格系と同じゾーン（ポータルセッション必須）

### 3-2. UI（index.html v2.12.0・特価もれ検出①のテーブル）
①「実績の設定漏れ」テーブルの上部、既存「✔ 選択を個別特価に追加（未反映）」ボタンの**隣に**追加:
```
👥 選択会員をグループに追加
```
（個別特価ボタンは残す＝併存。②③には付けない＝①専用）

クリック時 `openSalesGroupAddModal()`:
1. チェックされた①行から`customer_code`を重複除去して集める。0件ならtoast警告して終了
2. モーダル`#salesGroupAddModal`を開く。中身:
   - ラジオ「○ 既存グループに追加」→ グループ選択`<select>`（`spData.groups`から `group_name`）／「○ 新規グループを作成」→ グループ名`<input>`
   - 「追加する会員: N件」の表示（会員名を数件プレビュー）
   - 実行ボタン`submitSalesGroupAdd()`・キャンセル
3. `submitSalesGroupAdd()`: 選択に応じて`addCustomerCodesToGroup`を呼ぶ（既存→group_id、新規→group_name）
4. 成功後:
   - モーダルを閉じる
   - **spDataを再取得**してから該当グループの特別価格設定へ遷移（新規グループを`spData.groups`に反映させるため）。順序: `gasPost({action:'getSpecialPriceData'})` のコールバックで `spData=res; spSelectedGroupId=返ったgroup_id; switchToSettings(group_id);`
   - toast（下記の反映リマインドを必ず含める）

### 3-3. ⚠️ 反映リマインド（機能の目的達成に必須）
グループに会員を足しただけではBカートに特価は入らない。**特別価格設定で商品の特価を設定し「BCARTに反映」を押すまで、設定漏れは解消しない**。会員追加成功のtoastに必ず含める:
> 「N件の会員を『○○グループ』に追加しました。特別価格設定で商品の特価を設定し、『💎 BCARTに反映』を押してください（既に商品特価が設定済みのグループでも、新しい会員に適用するには再度『反映』が必要です）。」

（補足: 既存グループが既に商品×特価を持っている場合、`applyGroupPrices`は実効メンバー＝member_ids∪解決済みcustomer_codesで動くため、反映を押せば新会員にも適用される。この「反映を押す」ステップが抜けると漏れが残るので上記リマインドが重要）

### 3-4. guide.html §8（特価もれ検出）に追記
「実績の設定漏れ」の対処に、個別特価追加に加えて「選択会員をグループに追加」→特別価格設定で価格設定→反映、という導線を1段落追記。反映を押すまで漏れは解消しない旨も明記。
